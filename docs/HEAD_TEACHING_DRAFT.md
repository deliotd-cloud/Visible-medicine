## Exact draft-review contract and private storage

`lib/head-teaching-review-contract.ts` implements the bounded identity/validation contract for private draft notes and requested corrections. The server-context builder requires the actual imported head manifest revision, verifies every existing binding and recomputes SHA-256 of the full teaching packet before exposing its context. The context now pins the exact packet, head source, twenty-five concept IDs and five checklist labels under `head-teaching-draft-review-2`. Event/context envelope schemas are unchanged. Older fifteen-concept histories remain readable but stale; no resuming or upgrading into the expanded packet. Saved-envelope validation accepts only canonical timestamps, bounded positive versions, exact fields and `draft`/`changes-required` records. Unknown/malformed concepts, duplicates and more than twenty-five entries fail closed. Changed packet/source/checklist/concept context is stale; historical records are never treated as current decisions.

The contract explicitly rejects `approved`, `attested: true`, registration/clinical/publication claims and extra fields. Name/qualification text fields are self-reported, not credential verification. Current administrator access alone does not establish a radiologist qualification. Any later clinical sign-off needs a separately explicit authority/attestation policy bound to this packet.

`GET/POST /api/atlas-review/head-learning` use the existing `runClinicalReview` guard and per-document account/institution continuity. The route derives the principal server-side and passes the actual imported manifest into the context builder. POST requires same-origin bounded JSON and exactly the current packet/head/checklist tuple; no caller-supplied user or institution is accepted. `lib/head-teaching-review-store.ts` reuses the existing `atlas_personal_nested_review_events` table in an isolated head-teaching namespace (no new migration). Append is a single prepared `INSERT ... SELECT` with atomic expected-version comparison. No updates/deletes are used. Reads validate both the complete event and storage envelope; corrupt records fail closed. Histories are private to the account and institution, not an institution-wide approval queue. Existing deployed storage must already include migration 0008; absence fails closed, not automatic schema creation.

The private form starts with blank notes and explicitly loads a saved current draft. History refresh preserves text and never silently rebases an existing form. Stale records remain inspectable with their original hashes but cannot be resumed. Unknown/network-conflicted saves lock further saving until history is compared and a current entry or fresh draft explicitly loaded; writes are not automatically retried. Discarding unsaved edits requires confirmation and never deletes history. Before-unload warns about unsaved edits; no browser storage, clipboard upload, patient data, entitlement change or public publishing is introduced. `lib/head-teaching-review-client.ts` validates exact history ordering/cursors/context and confirms the returned save matches the submitted draft, revision and next version before reporting success.
