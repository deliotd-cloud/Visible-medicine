# Tour frame evaluation and teaching headings

Regional tours resolve their exact source structures once per evaluation, then derive the overview and step frames from that admitted list. Every new evaluation still checks the current source. There is no persistent source cache or unchecked public path for caller-supplied resolved structures. Existing single-frame APIs, camera validation, playback settings and optional-frame behavior remain intact.

Run `node scripts/test-tour-resolution-batch.mjs` from this Atlas checkout. It compares every registered tour and evidence packet with the SHA-pinned first-party preimage, checks refusal and restoration after mutation of the same catalogue object, and counts source scans. These work counts do not establish a production latency or frame-rate improvement. The `.ts.raw` fixture is text evidence and is excluded from TypeScript source discovery.

Eleven abdominal topic headings were corrected to avoid repeating the structure name. The complete resolver comparison restores only those eleven old titles and compares all9,936placements with the authenticated prior result; other fields and the remaining9,925placements must match. Teaching paragraphs, references, readiness, names, laterality and geometry are preserved.

After source changes, use the stock regional snapshot generator and Review metadata writers, then verify the complete types, production build and source-bound exports/imports. Generated files must not be hand-edited. Rendered-source revisions and material revisions retain independent clinical-review gates. No private decision is read, copied or migrated, and this implementation does not approve anatomy or establish patient-space registration.
