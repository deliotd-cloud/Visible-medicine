## Proposed regression acceptance cases for that future design

1. **Teaching-only fixture:** exact four neonatal ultrasound placements change only four nested teaching revisions/worksheet hashes; other 104 nested teaching and all 108 source/geometry revisions remain exact. Full renderer/build seal still records the teaching payload change. Root-body source, teaching, material and geometry revisions remain exact if no root-body display input changed.
2. **Data boundary refusal:** changing the payload schema, adding executable behavior, geometry labels, camera/visibility commands, material attributes or unrecognized fields fails closed or changes the geometry seal. Reordering/formatting cannot erase a meaningful change; exact source provenance is required.
3. **Renderer/label/camera/material/source controls:** mutate one permitted renderer module, a visible mesh label, camera/guide direction, material/opacity rule, geometry source bundle and source coordinate frame in separate cases. Each must invalidate the affected geometry revision and current worksheet; source edits must also change sourceHash. Unrelated geometry identities stay bound to their exact source.
4. **Checklist and track isolation:** geometry checklist changes invalidate geometry; teaching checklist or cited text changes invalidate the corresponding teaching track; imaging remains unavailable without acquired-image validation. A renderer-only change must not silently turn a stale decision current.
5. **Saved-review and API refusal:** old revision/material tokens, crossed structure/track/source frame, forged seal, missing dependency, and corrupt saved metadata remain rejected. No prior approval is copied, migrated or broadened; `viewer-only` is shown only when the exact recorded comparison proves it, otherwise `unavailable`.

These are acceptance criteria for a separate design/review, not a proposed source edit or approval decision.
