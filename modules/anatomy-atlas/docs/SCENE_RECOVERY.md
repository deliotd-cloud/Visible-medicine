# Recover an interrupted 3D view

The shoulder, all eleven regions and whole-body explorer now share a graphics-recovery surface. If the context is interrupted, the unavailable canvas and its labels are hidden and inert. A normal page control offers **Restart 3D view**, so recovery does not depend on drawing inside the failed canvas.

Practice cannot start, accept answers, skip or advance while its 3D viewer is unavailable. Existing answers are retained; exiting practice remains available. The shoulder additionally waits for its model to load successfully. Body model-group readiness remains separate from graphics readiness: a healthy graphics context does not make a failed download ready.

## State and restoration

- Starting → ready requires a successful guarded renderer call followed by a live-context probe. It no longer announces readiness in a callback that runs before rendering. This is renderer availability, not proof of correct pixels or anatomical correctness.
- A context-lost event prevents the default loss handling to permit restoration, then pauses the viewer. A healthy probe alone cannot leave the lost state: a restoration event must arrive first.
- Restoration schedules a frame. The observer confirms the context is available before allowing practice again; Three.js manages reconstruction of its graphics resources.
- Manual restart remounts only the graphics subtree. Selection, hidden tissue, systems, separation, inspection and practice state remain in the explorer above it. The last captured camera is copied only when the last healthy viewer's camera-intent key still matches. A newer preset, zoom or reset chosen while interrupted takes precedence, as does an explicitly queued saved-view camera. A never-ready viewer cannot reuse an older viewer's capture.
- Each attempt has a generation-bound callback. Retired viewers and disposed observers cannot revive a newer attempt. Listeners are removed on cleanup.
- Caught React scene errors, synchronous `render()` exceptions and Three.js shader-error callbacks display the same page-level recovery control. The per-renderer guard installs in the monitor's layout effect, preserves the original method receiver/arguments and existing shader callback, and stops further draws after failure. A shader failure cannot be followed by a misleading ready signal. Failure stays terminal for that observer, including after later context events.
- Cleanup restores only the hooks owned by that guard, preserving any later instrumentation. A retired guard cannot announce health. No global error or unhandled-rejection listener consumes unrelated page failures. Awaited configuration rejections and exceptions from this viewer's frame subscribers now reach the same recovery control. A still-pending initialization retains its starting notice and restart action; no fabricated timeout or automatic retry loop is introduced.
- After a user-initiated restart, keyboard focus returns to the named 3D region only if focus has not moved to another control. No whole-page reload, automatic retry loop, new storage write or network service is introduced.

The recovery notice uses Visible Medicine tokens, ordinary text and the installed button primitive. It stays outside the unavailable canvas. The source meshes, transforms, FMA/stable IDs, content, dissection recipes and imaging hooks are unchanged.

## Scoped startup and frame ownership

Both scenes now use `AnatomyCanvas`, an atlas-specific adapter over the installed R3F public root API. It awaits `configure()` and has a separate React boundary inside the R3F root. Its `AnatomyRootSession` installs a root-local invalidator and advances only that viewer. The original demand behavior is retained: invalidations coalesce; controls can request the next damping frame; idle viewers have no drawing queue. Manual advance receives elapsed **seconds**, not RAF milliseconds, and excludes unrelated global effects. Camera projection, scene graph, event manager, picking and subscriber priorities remain R3F's. There is no global animation-loop/error-handler patch.

The host uses ResizeObserver plus resize/scroll measurements; invalid or zero dimensions defer startup. Children and DPR update without replacing the live root. Unmount cancels queued frames, unsubscribes, restores only its owned invalidator and calls public root disposal. If configuration is still pending, retirement waits for that promise to settle without rendering anatomy or reporting stale health. Each restart gets a fresh physical canvas, so R3F's delayed old-root cleanup cannot remove the new root. Old scene-boundary callbacks retain their original session. A synchronous terminal-health latch rejects a late `ready` signal even before React commits the failure update.

The installed R3F 9.7 runtime can reject configuration before creating its Scene; its unmount cleanup nevertheless expects a Scene. On that terminal path only, the session obtains the existing store with `render(null)` and provides an empty disposal target. This does not render replacement anatomy or alter the private root registry. Store subscribers are deliberately not notified while the renderer is absent. A secondary setup error still reports failure. Real-reconciler tests verify that retired root records disappear. Recheck this contract when upgrading R3F; do not assume it applies unchanged to another release.

This adapter supports the current atlas's explicit scene props and R3F context, not arbitrary inherited DOM React contexts or third-party global frame hooks/WebXR. No such context consumers or global hooks are required by the current scene graph. Any future addition needs scoped integration tests. A renderer factory that never settles remains restartable but cannot be synchronously disposed while its resource creation is unfinished.

The canvas lifecycle covers zero-size startup, observe/update/resize/scroll, fresh-canvas remount, listener/queue cleanup and stale-callback isolation. This is stronger than injected-hook tests but still not a browser or GPU acceptance test.

Shader checks remain at Three.js's enabled default; disabling them elsewhere would bypass shader-error reporting. No third-party code, font, texture or model was imported for this feature.
