# PICA source-part explanations

Twenty-six existing source selections now have original file-bound Anatomy,
CT/MRI explanations and distinct unscored self-checks: 13 supplied files on each
side. These are not 26 validated anatomical branches. Open either PICA's source
component study in Head/neck or Whole body, select a file and expand the existing
Learn more panel. No new toolbar, panel, mesh or scan is introduced.

## What the drafts explain

Each note preserves the side, exact source file, source order and parent FMA.
File-specific source counts distinguish triangles and disconnected components
from clinically identified branches. FJ1701 and FJ1701M each contain two supplied
surface components; other included files have one. Each parent therefore retains
13 files/14 surface components. No connection or lumen repair is performed.

Thirteen paired teaching themes cover inherited parent FMA, disconnected pieces,
archive order versus anatomical segments, laterality during rotation, file edges
versus vessel junctions, parent supply versus perfusion territory, tessellation
versus calibre, visibility versus absence, noncontrast CT versus CTA, separate
CTA/MRA cohorts, explode layout versus surgical planes, supplied opposite-side
topology versus patient symmetry, and skipped filenames versus missing anatomy.
Each side/file has its own exact lesson/quiz identity; no geometry is mirrored or
substituted to make a counterpart.

The only general vascular Anatomy statement is explicitly **parent context**:
PICA usually arises from the vertebral artery and contributes medullary/inferior
cerebellar supply. It does not allocate a territory to any file. Function,
Clinical and Pathology remain pending **for the unidentified component**;
X-ray/US and acquired-image registration are also pending. Matching names,
archive order, plausible position or a visible draft is not anatomical sign-off.

## Binding, review and verification

`pica-source-teaching-bindings.v1.json` pins two complete parent records and all
26 complete selected records, parent and child bundle digests, side, frame/source
position, archive file/hash and concept identity. The pin script verifies the
explicit per-file topology facts against the existing partition proof and refuses
to overwrite existing changed pins. FMA alone cannot choose a source-file lesson.
Whole-record, source/side/order/frame changes reject content rather than silently
falling back to a parent or sibling. Returned lessons are detached JSON records.

The new transition checks all 108 nested source records: exactly 26 teaching
packets advance and the other 82 remain equal to the immutable prior source,
including all three MCA packets. Three core pending blockers still prevent
teaching approval for every PICA component, and imaging review remains unavailable.
Renderer-bound display revisions expire; decisions are never read or migrated.
Historical MCA/older corpus proofs retain immutable epochs and exact hash-guarded
projections rather than repinning prior snapshots to later material.
New references are concept-scoped: a shared source URL cannot overwrite the
title in an unrelated existing review packet. The exact 82-packet equality test
covers this safeguard against citation-title collisions.

Run `npm run pica-source-teaching:test`, affected cranial/nested teaching,
review/navigation/learning/practice and renderer-scope suites, then types/build
and exact inventory checks. Tests are not browser/GPU, clinical or public-release
acceptance. Full introductory source-teaching coverage is not a complete clinical
curriculum, finer branch identification, complete vascular tree or patient atlas.
Website import/deployment and radiologist adjudication remain separate steps.
