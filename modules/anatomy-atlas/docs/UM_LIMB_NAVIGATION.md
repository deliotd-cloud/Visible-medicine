# Independent lower-limb study links

## Using links

Select a structure in the independent specimen and expand **Link to this study**. Choose **3D model** or an available teaching topic, then copy the link or open its view. The picker includes only exact bound drafts. Automatic copying has a selectable-text fallback. The link stays in the existing side panel; no new permanent toolbar or body-atlas catalogue fetch is required.

A named study opens its exact tissue set, selected structure and one of six camera directions. Separation starts at zero, the undo/redo history is empty and practice is off. A custom dissection links to the selected structure framed against faded, assembled regional source context; it does not serialize arbitrary hidden tissues, free-orbit pose, separation distance, labels, history or quiz state. Anatomy/Function notes open only when explicitly requested.

The dedicated `/specimens/lower-limb` page uses the same compact specimen workbench and region switcher. Its server boundary parses only lightweight link data. The specimen implementation loads on the client, without mounting BodyExplorer or loading the other source body's catalogue. Back/Close uses a fixed regional destination: foot, thigh or leg. No return URL is accepted.

## Canonical contract

Generate links with `makeSpecimenLink` in `lib/um-limb-navigation.ts`, rather than manually constructing or shortening identity fields. The builder returns a same-site relative URL or `null`; the copy control adds only the current origin.

| Query field | Meaning |
| --- | --- |
| `specimen=um-limb-1` | Contract discriminator |
| `specimenScope` | `knee`, `hip-thigh`, `calf`, `foot` or `whole` |
| `specimenPart` | Exact `vm:reference:um-5t6tz7-v1-2:knee:*` or `...:lower-limb:*` ID |
| `specimenSource` | Selected part's declared bundle SHA256 |
| `specimenRevision` | Scope's pinned source/recipe revision |
| `specimenStudy` | Optional exact study ID; omission means structure-only context |
| `specimenView` | `anterior`, `posterior`, `right`, `left`, `superior` or `inferior` |
| `specimenTopic` | Optional `anatomy`, `function`, `clinical`, `pathology`, `ct`, `mri`, `xray` or `ultrasound`; exact bound draft required; omission keeps notes collapsed |

`lib/specimen-links.ts` rejects incomplete, duplicated, unknown namespaced and mixed body/specimen fields. It does not load source geometry or make authorization decisions. Unrelated query values are ignored and never copied into generated links. A same-route parameter change remounts the linked view, avoiding stale selection/history. Extended topic values are backwards-compatible additions; the resolver checks the actual pinned lesson and rejects a pending/unbound topic before mounting the viewer. Source-only and earlier Anatomy/Function links remain valid without repinning the unchanged source/recipe contracts.

`content/um-limb-navigation.v1.json` pins five complete contracts: source descriptors, all scope surfaces and bundle descriptors, coordinate system, study recipes and close-up bounds. The revision is SHA256 of canonical sorted-key JSON, generated by `scripts/pin-um-limb-navigation.mjs`. The resolver requires both the exact pinned revision and a byte-canonical match between the current definition and pinned payload. It then checks scope membership, the selected bundle hash and membership of the requested study. Grouped bones remain grouped; similarly named or differently sourced surfaces are never substituted.

Invalid or changed links display a warning without mounting the specimen renderer. The user can explicitly choose another scope or open the current source view and create a fresh link. Definitions do not auto-migrate old revisions. Repin only after deliberate source/recipe review; repinning is not clinical sign-off. Runtime checks concern metadata bindings, not cryptographic verification of downloaded GPU bytes; existing export suites verify artifact integrity separately. Teaching content has its own source/lesson pins and is not frozen historically by this navigation revision.

## Security, rights and imaging boundaries

Links do not grant permission. The site's existing private access remains in place; no Atlas subscription implies access to a separate paid lecture. A future teaching-resource resolver must independently check the user's entitlement before serving its content. No authentication/database/access-policy changes, new dependency, font, model, texture or external service was added.

These are independent specimen navigation IDs, not FMA mappings, patient identifiers, DICOM references or registrations. No credentials, scan coordinates, redirects, quiz answers or entitlement tokens are serialized. Future CT/MRI/X-ray/US projects may refer to this exact specimen as teaching context, but synchronized patient highlighting requires separately validated registration and approved manifests. There is no claim of automatic cross-subject alignment.

## Verification and remaining acceptance

`npm run um-limb-navigation:test` verifies manifest freshness and 446 generated round trips across all five scopes/26 study choices, including every selected member of every study. It checks malformed/changed/foreign bindings, custom source-context state, empty history, zero separation, explicit topic/view and installed React controls at the GPU boundary. The server route is exercised at its client boundary. Existing knee, limb and learning suites remain regression requirements, alongside TypeScript and production build.

Browser clipboard/back/forward behavior, GPU loading, responsive layout, keyboard/screen-reader usability and clinical suitability still need explicit acceptance. These source/component tests are not browser or clinical certification. No underlying anatomy, source meshes, review approvals or paid-resource availability has changed.
