# Comparison viewer: superseded-error protection

17 September 2026. Source implementation; no viewer/case is connected or
entitled by this change. Didanix Education/light remains the integration target.

## Reproduced defect and fix

A host callback can publish a newer comparison frame synchronously, then throw
while finishing its older operation. The request/mount catch paths previously
changed that newer frame to an error and cleared its anatomy. This could also
overwrite a newer loading or access-denied result. The asynchronous request
path already checked its initiating snapshot, but the synchronous paths did not.

The shared failure helper now accepts the exact initiating snapshot and refuses
to mutate state unless both adapter ownership and snapshot identity still match.
The rule applies to slice, plane and mount errors (including invalid mount
disposers) and promise rejections. Genuine current failures still fail closed;
old controls remain unusable. No request grants access, supplies registration,
reads patient data or changes the anatomy view.

## Verification

`imaging-comparison:test` first reproduced the defect at
`slice/ready/throw`; after the runtime fix, all 18 combinations of slice/plane/
mount, ready/loading/access-denied and synchronous/asynchronous or invalid-
disposer failures pass. Two current mount failures still clear the mapping.
Existing source/side, access/exam, control bounds, lifecycle, immutable data,
identity bridge and actual React-markup checks remain intact.

`didanix-adapter:test` and `volume-viewer:test` pass with synthetic data only.
`independent-navigation:test` exposed a separate Node-harness import mismatch:
the application uses Vinext's installed `next/link` compatibility implementation,
but the harness attempted to load absent Next.js. Loading the same installed
`vinext/shims/link` implementation fixes the harness without fake links or
weaker assertions. Its existing checks pass.

TypeScript and source/module build outcomes, review revision, exact commits and
backups are recorded in the coordinating checkpoint. No new browser/GPU,
physical-device, clinical, live-case or deployed-site acceptance is claimed.

No models, educational content, scans, masks, licences, dependencies or
independent case/Atlas/lecture access policies changed. Existing approvals are
not migrated; the renderer fingerprint is regenerated by the normal build.
