# Local reference packet inspector proposal

Draft, isolated source files for a reusable private Clinical Review component. No packet, article text, image, source registry, inbox entry, route or asset is included here. The existing study/annotation loader and learner flows remain separate.

## Contract

- Render only `vm-published-ultrasound-review-packet/1` with all current fields present and no unknown fields. Every approval/readiness/import/write boolean must be `false`; mappings must be `null`; figure review states remain `not-reviewed` and publication `not-cleared`. Figure 6 requires a nonempty additional rights hold. A null hold on another figure means only that no *additional* hold was recorded.
- User selects one folder directly containing `REVIEW_PACKET.json` and each declared JPEG. The exact optional companions `review.html` and `THIRD_PARTY_NOTICES.txt` may be present in the same folder. They are counted and size-bounded but **never read, rendered or executed**. No fetch, remote image URL, storage, decision call, network request or server endpoint exists in these files. Source URLs are rendered as escaped text, never fetched by the component. The selected local JPEG bytes become short-lived blob URLs only after byte counts, SHA-256, encoded dimensions and browser decode match the packet.
- `revisionSha256` is SHA-256 of `JSON.stringify(packetWithoutRevisionSha256)`. `packetSha256` is SHA-256 of the exact selected JSON bytes. When a parent supplies `expectedRevision` and `expectedPacketSha256`, both must match. Self-consistency and optional caller pins do not prove the caller's trust, source authenticity, person identity, rights, privacy clearance or clinical approval.
- On invalid replacement the previous verified packet remains visible. New selections abort older reads. A stale result disposes its blob URLs. Successful replacement retires old URLs after the new React commit; Close, source-pin change and unmount dispose active and retired URLs. The loader disposes partial URLs on every thrown error. User Close restores focus to the picker; source-pin cleanup leaves focus alone. A detached image error is ignored unless its element is still the committed image and its packet and selection are current.
- File count ≤15, packet ≤128 KiB, each optional companion ≤128 KiB, each JPEG ≤16 MiB, all JPEGs ≤96 MiB, each dimension ≤4096, each image ≤16 million pixels. Paths must be direct children of one selected folder, with no case-insensitive duplicates or unknown extras. There are 1–12 figures. These limits are a proposal and should be reconciled against future legitimate packet sizes before integration.
- Duplicate JSON object keys are refused before validation, including escaped spellings and nested object keys. The bounded token walk uses `JSON.parse` for valid syntax and decoded key values, with a nesting limit of 32.

## Verification and integration left to main

`node --max-old-space-size=512 --experimental-strip-types --test tests/local-reference-review.test.mjs` exercises synthetic, nonmedical packet metadata and marker bytes, including the exact eight-file folder shape, unread companions, duplicate JSON keys and partial URL disposal after abort. The test stubs browser JPEG decode and blob URLs; it does not establish real browser decoding, layout, keyboard/focus acceptance, source authenticity or clinical clearance.

Before integration, validate against the **actual current source** and expected packet hash under main ownership, run focused types/build and native browser checks with a generated nonmedical JPEG, including rapid replacement/unmount and narrow viewport. Decide how a protected parent supplies trustworthy revision and exact packet-byte pins without importing packet JSON or originals into hosted code. Keep the current private access checks and separate inbox route unchanged until that delivery question is resolved. No public article packet should be registered or copied into a build on the strength of this proposal.
