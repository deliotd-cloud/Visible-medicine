# Current test delivery after keyboard Help binding

The policy in `docs/CURRENT_ATLAS_TEST_DELIVERY.md` permits a staged current
fixture advance only after clean source, generated runtime exports, protected
Review bind/build, model and rights scope, and changed fields are checked.
This proposal uses the exact verified Help fixture for the c48 website and
keeps the native a01 source/tree and all four runtime sources unchanged.

The previous default pin, unchanged validator and whole current test are
retained byte-for-byte in `tests/fixtures/current-delivery-before-help-d55/`.
The previous ordered Review input metadata is retained there as well. The
transition test checks these hashes, all 12 current metadata hashes, the same
1,818 input identities and exactly two changed presentation input hashes. It
also reconstructs the complete previous test source from the new source using
only named current-expectation seams. Historical case names, source hashes,
refusals and inverse proofs remain present.

This is test admission metadata for an isolated candidate. It does not record
clinical approval, rights clearance, patient registration, release readiness,
installed cutover or a completed stock suite. The separate
`tests/current-ui-delivery-transition.test.mjs` still asserts the historical
9e delivery as if it were the current default; it needs a distinct historical
epoch role repair before its result can be interpreted.

Main additionally retains the previous Review and Viewer metadata and checks the advanced pin refuses those original bytes. Frozen source is an integrity/history record; no claim is made that every earlier mutually stale current assertion passed. The production validator, clinical decisions, source meshes and access rules remain unchanged.
