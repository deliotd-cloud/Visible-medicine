# My Learning section availability

The signed-in page loads progress, portfolio, profile and enrolments once each. An optional loader returns an unavailable result only for six exact ordinary-Error messages documented by [Cloudflare D1](https://developers.cloudflare.com/d1/observability/debug-d1/) (checked27October2026). Network loss, replica disconnection, transient resolution, code reset and the two overload messages are admitted. No prefix-only matching, recursive cause unwrapping, automatic retry, timeout or logging is introduced.

Authentication executes first. Unknown errors, schema/constraint/integrity errors, framework navigation and metadata-bearing authorization errors propagate unchanged. Database functions, their existing provisioning/cleanup effects and all entitlement checks remain unchanged. This UI recovery does not claim that a failed operation made no writes.

Unavailable data is distinct from a successful empty array. Metrics, section empty states and profile completion are never fabricated. Loaded portfolio forms receive static Atlas choices plus successfully loaded saved/enrolled resources, with an incomplete-choice notice when needed. If enrolments fail, saved course links fall back through the existing destination policy to course details/catalogue; a progress row never grants a workbook resume.

A single native reload link is deliberate and remains subject to existing unsaved-draft unload protection. No background reload or client storage is added. Tests exercise every source failure, combinations, positive empty results, authentication before data, refused failures and no secret error text in rendered UI. Synthetic browser/SSR evidence is not signed-in account or production outage acceptance.
