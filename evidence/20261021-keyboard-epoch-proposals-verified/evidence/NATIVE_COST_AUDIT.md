# Native suite cost audit — 21 October 2026

## One candidate: reuse only the lower venous bundle *bytes* within its test file

The frozen source190 website's `tests/atlas-lower-venous-tour.test.ts` calls `load()` and `load(true)` in each of its two registrations (lines 25, 71). Each `load` calls `build` and imports its output (lines 15–22): four bundle transformations for one file invocation. The first registration verifies tour, catalogue, imports, file hashes and emitted teaching (lines 24–68). The second verifies all 9,936 topics over 1,104 structures, six changed worksheets, 36 malformed evidence refusals and six stale submissions before storage (lines 70–87). The existing historical helper already caches individual immutable Git blobs in process (`atlas-pre-lower-venous-reasoning-history.ts`, lines 8–17), but its `build` wrapper still invokes esbuild for each call (lines 18–24). `old()` in the test (line 12) remains uncached for a smaller set of baseline comparisons. Thus this candidate targets repeated transforms, without assuming Git reads or the topic loop dominate elapsed time.

The live suite child log reports 76,140.9 ms and 46,442.1 ms for these cases (lines 412–413); these are whole-case durations, **not** transform measurements. A second representative, `tests/atlas-hand-venous-imaging-checks.mjs`, has two builds in its single registration (lines 13–20), then explicit 9,908 preserved topic placements, 1,104 source mutations, 112 malformed packets, 14 stale refusals, per-file hashes and emitted teaching checks (lines 27–70); its whole case took 252,937.8 ms (log line 352). This supports measuring phases before inferring the suite's bottleneck. No speedup estimate is justified yet.

## Proposed future scope and gate

Instrument only the lower venous test in a separate proposal: time each `build`, dynamic import, Git replay/cache miss, emitted-file/hash pass and the 1,104-structure loop with `performance.now`, logging local phase totals without changing assertions. Capture a same-source baseline and then benchmark an in-process, per-file two-entry promise cache of *bundle output bytes* keyed by current versus historical build. Instantiate a fresh module namespace for each registration (unique data-URL identity or equivalent), so assertions cannot inherit mutated module state. Keep cache lifetime within one test process; never persist it between source revisions. Preserve the Git epoch/cache, exact historical onLoad behavior and all current manifest/model/source hashes. The runner must still snapshot inputs and refuse drift independently; bundle reuse must not replace any source guard.

Acceptance: compare phase and whole-case timings under the same frozen input identity, repeat enough to distinguish variance; run both original registrations individually and together, asserting unchanged case names, counts, 9,936/1,098/6/36/6 totals, all historical/current file checks and fail-closed mutations. Alter a relevant current file and a historical fixture separately in disposable copies: each must invalidate/refuse independently. Do not install the change if measured savings are negligible or if isolation or source invalidation cannot be demonstrated. Preserve the current live suite and its receipt; no broad test/build was run for this audit.
