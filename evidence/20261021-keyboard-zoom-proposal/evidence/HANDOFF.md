# Focused anatomical-model keyboard zoom

Opt-in +/= and −/_ zoom uses the existing, focused model/tray keyboard handler, not a document-level shortcut or additional listener. Control/Command/Alt, composition, other targets, lost focus, disabled controls and `enableZoom=false` remain untouched. The common `FittedCamera` opts in for ordinary spatial and planar views; its guided-camera `locked` guard remains unchanged. This is not the native CT/MRI acquired-surface camera or the owner's desktop PACS.

Perspective zoom changes distance from the current target. Orthographic zoom changes projection scale, without moving the target or named projection. Existing controller distance/zoom limits apply; out-of-range wheel poses do not reverse the requested direction. Invalid numerical state and unsupported cameras are refused. Keyboard steps retain the existing immediate input policy, and callbacks capture/invalidate the new live pose so refits and relative saved-camera state keep the user's view. No source geometry, anatomical identity, selection, scan position, physical measurement or clinical state changes.

Only `lib/camera-keyboard.ts` and `app/fitted-camera.tsx` change at runtime. Both already belong to the renderer revision input list; no unbound helper, dependency, asset, font, service or fee is introduced. A new focused script exercises the real Three.js camera/controllers and actual compiled FittedCamera hook, while the complete original 14-case keyboard script stays byte-exact. Native focused coverage totals23 cases, not23new cases or whole-app acceptance. Source, typing, renderer and stock integration gates still apply before delivery.
